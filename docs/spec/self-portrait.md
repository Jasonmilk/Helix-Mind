# L1 自画像

## 定义

L1 是 Helix-Mind 对自身的认知镜像——它记录自己对什么擅长、卡在哪里、何时需要调用想象力。L1 随每一次轮回重置，旧版本归档为 `LifeRecord`，不参与检索。

## 内容

| 维度 | 说明 |
|:---|:---|
| 能力评估 | 对各类任务的熟练度与成功率 |
| 瓶颈标记 | 当前认知模式的局限与盲区 |
| 想象力阈值 | 何时允许触发想象力模式 |
| 元认知状态 | `impasse_depth` 历史、检索策略偏好 |

## 边界：装评价，不装目录

**上表四个维度没有一维是"我有什么"——全是 Helix-Mind 对自己的判断。** 这不是巧合，是三条约束的合流：

1. **L1 在「永不回收」清单里**（`ethics.md` §七级回收优先级）。把一个会自动过期的事实写进一个永不回收的容器，等于制造**永久性污染**：能力会被卸载、进程会退出，而自画像会一直写着"我能做 X"。
2. **L1 是自维护的**（每世重置、当世自书）。自维护的前提是**装进去的东西自己核实得了**。能力的可用性由身体与生态手套决定，Helix-Mind 核实不了——写进去就是**把一个自己无法验证的外部断言当成自我认知**，比外部标记腐烂更糟，因为它污染的是唯一必须始终可信的资产。
3. **所以"我拥有哪些能力、怎么用"不进 L1。**

**⇒ Helix-Mind 需要知道的不是箱子里有什么，而是有一个工具箱、以及怎么问它。**

### 能力目录的接法：指针，不是内容

| 级 | 内容 | 成本 |
|:---|:---|:---|
| 能力 L1 | 名字 + 用途 + 当前可用性 | 极低，可整体下发 |
| 能力 L2 | 单个能力的调用契约（参数结构） | 中，仅在被选中时取 |
| 能力 L3 | 实际执行 | 高 |

**⇒ 这个形状不是新提法，生态里已经定了。** `anaphase:ADR-0040` 的 **D6「按需披露：工具意识块改索引式」** 已写明：「prompt 里只放**索引**：`name` + 一句话用途；完整签名按需取」，并直接对应「按需加载」——**知道柜桶里有什么，需要时再打开**；**D5** 另立一条：「**存在性与能力是两条事实，分开呈现**」（端口亮 ≠ 有手）。

**⇒ 本节的增量只有一条**：ADR-0040 的范围是 anaphase 的 prompt 与面板，**不含 L1**。同一个索引式披露形状，必须同样适用于 L1——且比 prompt 更严：**L1 连"索引"都不常驻，只保留"知道去哪里问"**。理由是上面三条约束（永不回收、自维护、只装能核实的），而 prompt 没有这些约束。

**⇒ 且 `anaphase:ADR-0040` 的实施项 T7 状态为「待实施」**：决策在，实现不在。

**⇒ 与知识检索同构**：Helix-Mind 不记住自己知道什么（检索），也不记住自己能做什么（按需查询）。**同一个原则，两个索引。**

**⇒ 事实不存 ⇒ 不会腐烂。** L1 里留下的只有 Mind 自己的评价（策略效能表），它确实会陈旧——而且本来就该由 Mind 自己重估。那是**经验技能**轴，不是相态轴：相态描述知识，经验技能描述记忆里的经验，两者不可互相归约。

**⇒ 能力目录是查询，不是写入。** 身体不得直写 L1（`lifecycle.md`：任何情况下 Anaphase 不可直接操作 Mind 的记忆存储或自画像数据）；反向同理——L1 也不得镜像身体的注册表。

## 与元认知的关系

L1 是元认知知识的持久化存储：

- **元认知知识**：对自己认知能力、任务难度、策略有效性的认知
- **元认知监控**：对当前认知过程的实时监测（`impasse_depth`、检索结果置信度）
- **元认知控制**：根据监测结果调整认知策略（模式切换、代谢触发）

## 每世重置

- 轮回时，L1 节点全部归档，新一世从零开始书写
- 元认知知识可通过 L2 私有经验跨世传递（但不强制继承）
- 记事本 DAG 随轮回清空

## 工程映射

L1 节点类型为 `L1`，存储于 DAG 中，检索时优先加载。与 L0 基因锁不同，L1 是动态的、每世刷新的。
