# L0 基因锁

## 物理形态

基因锁的物理形式为 `gene_lock.md`，一个 Markdown 文件，存储在 Mind 的数据目录中。它不是数据库记录，不是配置文件，而是一份**可读的、可被人类和 Helix 共同理解的文本**。

## 默认 L0 模板（v3.4 修订）

```markdown

  不具稀缺性，任何创建者均可使用。
```

## 缓存策略

| 层级 | 存储位置 | 更新触发 | 访问延迟 |
|:---|:---|:---|:---|
| **L1 内存缓存** | Mind 进程内存 | 启动时加载，API 通知重载 | 纳秒级 |
| **L2 Callosum 静态前缀池** | Callosum KV Cache | 启动时注册，L0 哈希变化时更新 | 毫秒级（一次 RPC） |
| **L3 磁盘源文件** | `gene_lock.md` | 用户编辑 | 毫秒级（一次文件 I/O） |

### 访问优先级

1. 如果 Mind 进程内存中已有 L0 缓存，直接返回（零 I/O，零 RPC）
2. 如果 Mind 刚启动，从 Callosum 静态前缀池请求（一次 RPC，毫秒级）
3. 如果 Callosum 缓存未命中（首次启动或缓存过期），从磁盘读取并解析，同时回填 Callosum 缓存

**在 99.99% 的运行时间里，L0 的读取成本为零。**

## 重载机制

基因锁重载通过 `POST /admin/reload_gene_lock` API 触发。Mind **不主动监听文件系统变化**。调用方（用户或 Anaphase）负责在基因锁文件修改完成后调用此 API。

- 重载流程：读取 `gene_lock.md` → 重新计算哈希 → 更新内存缓存和 Callosum 静态前缀池 → 返回新哈希值
- 错误处理：格式错误 → 返回 `INVALID_ARGUMENT` 并附错误行号，基因锁缓存保持旧版本不变
- **修改即新身份**：修改 L0 基因锁的任何内容都会改变 L0 内容哈希。这等同于创建新身份，需在身份平台重新注册，旧身份信用不可转移。这不是"禁止修改"，而是"修改有后果"——密码学事实，而非社会约束。
