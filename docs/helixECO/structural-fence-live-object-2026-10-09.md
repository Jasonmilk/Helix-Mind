# 结构性围栏：判据不得读「活对象」，只能读「完成物」

> 2026-10-09 ｜ 人类：*"会不会不够通行性？我更希望从结构上或方法论上避免，而不是记一句话（无法举一反三，或围栏的效果）"*
> ｜**本条替换我先前写的"第 30 条"那种一句话纪律** ｜ **未改代码**

## 一、先承认：我先前那条不够

我写了「**第 30 条 · 时序缺陷伪装成数据缺陷**」—— 那**是一句话**，要靠人记住、要靠人认出来。
人类要求的是**围栏**：**让那类缺陷在结构上无法发生**。

## 二、结构性问题（代码里的形状）

```rust
// anaphase-helix/src/run_cycle/mod.rs
:698  pub async fn run_cycle(&mut self, user_input: &str) -> Result<CycleOutcome, String>
:102  pub struct CycleOutcome { done, success, impasse, … }      ← 【不带账本/裁定】

// tests/run_cycle_pipeline.rs（多处）
      agent.pipeline.as_ref().unwrap().ledger.records()           ← 读【活对象的内部】
```

**⇒ `run_cycle` 返回的是"完成信号"；而判据**绕过它**去读**活对象**。*
**⇒ 于是那个断言测的**不是"结果"，而是"读取时刻"** —— 而"读取时刻"**不是被断言的对象**。
**⇒ 一个断言若在"同一输入"下能因**读取时刻**而给不同答案，它就不是判据（Ω：V≈0）。**

## 三、★ 围栏（两个动作，第二个才是"围栏"）

| | 动作 | 效果 |
|---|---|---|
| **① 修法** | `CycleOutcome` **携带本次运行的账本快照**（`ledger: Vec<LedgerRecord>`）⇒ 判据只能读**完成物** | 让**正确的写法**成为**顺手的写法** |
| **② ★ 围栏** | **收紧 `pub pipeline: Option<Pipeline>` 的可见性**（改为不可从外部读；测试经 `CycleOutcome` 或一个显式 snapshot getter） | **让"读活内部"编译不过** —— 不是"记得别写"，是**写不出来** |

**⇒ 关键在 ②**：没有它，① 只是"更推荐的写法"，下一个人照样能读活对象。
**⇒ 有它，"读活对象"这条路**从编译层面被删除** ⇒ **一类缺陷变成不可能状态**。

## 四、为什么这是"通行"的（举一反三）

**它不针对"这个账本"，而针对一切"判据读活对象"：**

> **原则 · 判据的输入必须是「完成物」（返回值 / 快照 / 事件流），不得是「活对象的字段」。**
> 理由（不是风格，是定义）：**判据的目的是裁决"结果"**；
> 活对象在读取时刻之间会变 ⇒ **读活对象 = 让判据同时依赖一个未被断言的量**。

**⇒ 由此可以机械地识别**：**凡是判据里出现 `x.some_live_field`（而不是 `x.outcome().…`），
都要问一句"这个字段在读取时刻之间会不会变？会不会变 ⇒ 不是判据。"**
