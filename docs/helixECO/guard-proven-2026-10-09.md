# ★ 守卫首次被证明有效 + 它抓出一条天然 V=0 闸门 + B1 的两条候选修法

> 2026-10-09 ｜ 已推 `phyt-DNA@e0a5bea` ｜ **B2 完成；B1 待一句话**

## 一、★★★ 悬了两轮的事：**「守卫能抓住判据退化」第一次被证明**

```
① DNA 闸门 →  [夹具无效] 注入前后的结论完全相同 ⇒ 夹具没越阈，或判据对该文件的内容不敏感
              exit=2                                    ← ★ 抓到了
② 正常闸门 →  基线绿 → 注入后 RED → 反例守住 ✅ → exit=0   ← 照常活着
```

**修法（B2，机械）**：**正例阶段比较【注入前后】的结论。若一字不差 ⇒ 这次 RED 不是夹具的功劳** ——
要么夹具没越阈，要么**判据对该文件的内容不敏感** ⇒ **具名报 `[夹具无效]` + 账本记 block + exit 2。**

**⇒ 而被它抓住的那条闸门**不是造出来的** —— 它是这个仓里**天然长出来的** V=0：**

```yaml
applies-to: ["DNA.md"]
check: |
  [ "$F" = "DNA.md" ] && echo "DNA 不可变: 禁止写入 $F（改基因 = 修宪…）"
```

**只看**文件名**，不读内容；而 `applies-to` 恰好把它解析成 `DNA.md` ⇒ **恒真 ⇒ 恒红 ⇒ V=0**。**
**⇒ 此前探针把它报成「心跳 RED ✅ + 反例守住 ✅」—— 两条都是**假的安心**。**

**⇒ 这印证了审查的判断：它不是"待修的缺陷"，是**守卫该抓的那一类退化**。**

## 二、⚠️ 新后果（必须点名）：**CI 第 3 步现在会红**

CI 第 3 步是**逐条 `--probe`**，非 0 即 fail。**实测那条闸门的 `--probe` 现在 `exit=2`**
⇒ **推上去的 CI 从此是红的。**

**⇒ 这是诚实的**（那条闸门确实有病），**但它意味着 `B1` 现在是**急事** —— 不能停在"CI 红着"。**

## 三、B1 的两条候选（我**未擅动**，等你一句话）

### 候选 ①（**极致复用**，我倾向）：把 `DNA.md` 纳入**已有的**资产基线

`tools/check-baseline.sh` 的 `calc()` 现在是 `find decisions tools`。**把 `DNA.md` 加进去** ⇒
**"DNA 不可改"就由 CI 第 1 步（已经存在的那一步）来守** ⇒ 然后**退役**那条恒红的 `check`。

- **好处**：**不新增机制**（G4 唯一真源 / A5 不允许第二份清单）；CI 第 1 步本来就在跑
- **代价**：`tools/check-baseline.sh` 的**职责范围**变了（从 "decisions+tools" 扩到 "含 DNA"）
- **语义正好**：DNA 改动 ⇒ 基线不符 ⇒ 红 ⇒ **必须走"刷基线"这个动作**（而按本仓规矩，那要过 ADR）

### 候选 ②：让 `check` 自己读内容

在 ADR 里声明 `dna-sha256: <hash>`，check 比对 DNA.md 当前 sha256 与该字段。
- **好处**：自包含；可双向（改了 ADR 字段就绿 ⇒ 正是"走 ADR"的语义）
- **代价**：**多一份哈希真相**（与 `baseline.sha256` 并存 ⇒ 违 A5 的味道）

**⇒ 我倾向 ①**（复用既有机制，且不新增真相）。

## 四、两条修法都涉及的两个"不擅动"理由（说清）

1. **`DNA.md` 的不可变性** ⇒ 动与它相关的机制，本身就在"修宪"边缘 —— 需你批准
2. **`decisions/` 改动须刷 `tools/baseline.sha256`** ⇒ 任何改 `check` 的方案都要连带刷基线
