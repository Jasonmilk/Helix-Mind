# 变异测试的闭环 + 「所见即所得」是我们共享视界的机制

> 2026-10-09 ｜ 人类：*"要做好变异测试的闭环，一方面方便未来维护，一方面适合测试"*
> ｜*"cellrix 就是碳基与轨迹，所见即所得，不需要 OCR —— 做通了，你不需要那么麻烦就能和我看同一个视界"* ｜ 已落地

## 一、闭环的缺口在哪（我自己的）

上一轮我建了三件东西：`fixtures/` · `tools/validate.sh --probe` · `ledger/`。
**但它们没有连成一个环**：探针跑完**不留痕** ⇒
**"我没跑过它"与"我跑过、它红了"在账本上无法区分**。**⇒ 那不算闭环，那是一次性动作。**

## 二、已补：注入 → 检查 → **记录** → 还原（`Cellrix@8f25db0`）

```
rec()          按 template/ledger/README.md 的 schema 写一行（kind: "probe" 是模板已定义的类别）
probe_one()    拓扑失配 / 缺夹具 / 不越阈 —— 三种结局**各自具名并留 block 记录**，不静默
--probe-all    无 target 时的默认动作（闭环应当一条命令跑完）；
               **无夹具的闸门具名跳过**（[具名跳过] 而不是悄悄略过）
event_id 唯一  <id>-<epoch>-<pid>-<rand>（先写成秒级会重复 —— 我自测时发现的）
```

**实测**：
```
probe-all                    → 心跳 RED · exit=0 · 账本 +1 {kind:probe, verdict:pass} ✅
夹具改成 `true`（不越阈）      → "心跳 NOT RED — 闸门已腐化" · exit=2
                               · 账本 +1 {verdict:block, note:"corrupted: fixture did not cross the threshold"} ✅
还原后 assets 无污染 ✅   两次跑 event_id 唯一 ✅
```

## 三、★ 闭环的**真正含义**：不只闸门被测，**"测闸门的东西"也被测**

第 ③ 步（把夹具改成不越阈）是**对测试框架自身的证伪**。
**⇒ 夹具腐化会被点名（"闸门已腐化" + block 记账），不会伪装成通过。**
**⇒ 这才是"方便未来维护"的部分**：后人改坏了夹具，账本上看得见。

## 四、★ 人类那条「所见即所得」—— 它是我们共享视界的机制，不是比喻

人类说：**cellrix = 碳基与轨迹，所见即所得，不需要 OCR。做通了，就不必那么麻烦才能看同一个视界。**

**⇒ 这与本轮 P3 的验证方式完全一致，且解释了为什么那种方式是**对的**：**

| 我做了什么 | 为什么它正是"共享视界" |
|---|---|
| 用 **CDP 读 DOM/调用面板自己的函数**（而非截图 + 视觉） | 面板绘制的那份 DOM **就是**人类看到的那份 ⇒ 我读的是**同一个对象**，不是它的图片 |
| 量到 `默认 24 段/405 行` vs `period 1 段/15 行` | 人类在界面上看到"混着"或"只有这一段"，是**同一个量的两种读法** |
| 未采用截图/OCR | **不需要**：取数即可比对，且可复现、可入账 |

**⇒ 因此"不必那么麻烦"的具体形式是**：把**面板自己渲染所依据的数据**做成可读接口（它已经是：
`/api/sessions` + `/api/events` + 浏览器里的 `Cx.loadWindow`），
**我与人读同一个来源 ⇒ 我看到的就是你看到的**（且我能把它写进 ledger 作为证据）。

**⇒ 建议记入 Cellrix 的方法论**（本文即凭据）：**"面板的渲染中间态必须可被机器读到"** ——
它同时满足"所见即所得"、可测试性、与"物理事实优先"（读事实，不读像素）。
