# C 渲染面 · 验证阻塞（实测，2026-10-09）

> **结论先说**：目标 2 指定的验证落点 **`web/tests/all_views_test.js` 在本机不执行**。
> 往那里写断言 = 写一条**永不运行**的测试 —— 该仓自己的文档判定这**比没有测试更糟**
> （"它的存在读起来像覆盖率"）。

## 一、实测

```
$ node -e "require('jsdom')"
→ jsdom MISSING
```

- `web/tests/` 下 **30 个文件**声明 `REQUIRES = 'jsdom'` 或 `require('jsdom')`。
- 它们的失败模式是 **`console.log('NEEDS-INPUT: jsdom 未安装'); process.exit(3)`** ——
  **不是失败，是"没跑"**，而且**看起来像被声明过的依赖缺失**（一种体面的绿）。
- `panel_tree_test.js` 自己就在 **L76 / L166 / L210** 三处重复同一句 `process.exit(3)`。
- **`panel_tree.js` 本身没有 `Date.now()` / `Math.random()`** ⇒ 目标 3 的"render 纯"
  在**既有渲染路径上已经成立**；新加的三块只要不引入非纯源即可。

## 二、这对目标 2 意味着什么

目标 2 的两条存活验证（① 字段穿过代理到浏览器 ② 活过整块重画）**都需要一个真 DOM 或 jsdom**：

| 路 | 代价 | 判断 |
|---|---|---|
| 装 jsdom | 引入一个前端依赖 | 与「不引入容器与构建体系」的边界相冲 —— **该由人类裁** |
| 手写最小 DOM stub | 约 40 行测试夹具 | 可行，且**不引入依赖**；但断言必须落在 **stub 上的渲染输出**，否则又踩第 7 条陷阱 |
| 写进 jsdom 族 | 零 | **等于没写** —— 本文件就是为否定这一条而写 |

⇒ 我**没有**往 `all_views_test.js` 里塞断言（那会产出一条永不运行的测试）。

## 三、另一条独立发现（既存，非本轮引入）

`panel_tree_test.js` 的结构是：**纯函数段（vm + `{}` sandbox，无需 DOM）先跑并打印**，
然后 DOM 段 `process.exit(3)` 退出。⇒ 纯段的结论**会打印，但整个文件仍记为 NEEDS-INPUT**。
**"跑了但不算数"与"没跑"在账面上同名** —— 与第 9 条陷阱（边界型/债务型）同族。

## 四、因此下一步的正确形状

在 `panel_tree_test.js` 里**手写最小 DOM stub**，把断言落在 **stub 上的渲染输出**：

1. **可寻址（碳硅同构）**：逐元素断言 `data-role` / `data-status` / `data-current` /
   `data-action|when|who` 都在渲染结果里 —— **人类看到几块，AI 就能指到几块**。
2. **render 纯**：同一 state 渲染两次 ⇒ 输出**逐字节相同**；变异「注入 `Date.now()`」⇒ 红。
3. **活过重画**：同一 box 上再渲染一次 ⇒ 三块仍在（对应 `session_list.js:158` 的整块重画）。

⇒ 这样不需要 jsdom、不引入依赖，且断言落在**渲染输出**上（不踩第 7 条陷阱）。
