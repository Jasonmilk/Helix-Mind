# ⚠️ 我读错了世界 —— 撤回"phyt-DNA 自身三点不合规"，并把它变成机械修复

## 一、撤回

我先前据 `--probe-all` 的输出报告：

> *"本仓自身三点不合规：`PLAN.md 177 行 > 150` · `layer1 三层合计 326 行 > 280` · `装饰性检查残留: examples/phyt.yml`"*

**⇒ 三条都是错的。** 实测仓库真实状态：

```
PLAN.md            26 行          （不是 177）
DNA+RNA+SPEC      175 行          （不是 326）
examples/phyt.yml 无 git diff --exit-code 残留
```

**⇒ 那三条 RED 是【夹具注入后】的世界** —— 夹具把违规注进去、闸门检出 ⇒ **那是夹具的功劳，不是仓库的病。**

## 二、为什么我会读错（这才是要点）

**`--probe-all` 的输出只报了一个世界（注入后）。** 而 `--probe-all` 的**每一行**都是注入态 ⇒
**读它的人会自然地把"夹具造出的违规"当成"仓库的状态"。**

**⇒ 这与本方法论最反对的那类缺陷**同形**：**
- **一个值**（RED）**被当成另一个量**（仓库合规性）；
- **"检出"≠"仓库现在违规"** —— 前者说的是**闸门活着**，后者说的是**仓库有病**。
（同族：`已就绪` 是端口的属性、`mtime` 是签出的属性、`--nocapture 无日志` 不是"没执行"。）

**⇒ 幸好我按"动手"先去看现场**：若直接改 `DNA.md` / `RNA.md` / `SPEC.md` / `PLAN.md` 去"变短"，
**我会为了一个不存在的病去动权威文档。**

## 三、修法（机械，不是提醒）

`tools/validate.sh` 的 `probe_one` 现在**每条都报两个世界**：

```
基线（未注入）: 绿
注入后: RED — 检出: PLAN.md      177 行 > 150
反例守住 — 内容未变时不红 ✅
```

**⇒ 一跑立刻显出差别：**

| 闸门 | 基线（未注入） |
|---|---|
| GROWTH-max-3 · PLAN-must-exist · PLAN-150-lines · layer1-280 · lesson-must-land | **绿** |
| **ADR-20261009-DNA-is-immutable** | **★ 红** |

**⇒ 真正的基线红只有一条：`DNA-is-immutable`** —— **而我先前报告的恰恰不是它。**
**⇒ 这就是"报两个世界"的价值：它把"闸门活着"与"仓库有病"分开了。**
