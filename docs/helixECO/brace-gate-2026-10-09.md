## 一、人类那句话（我理解为判据）

**⇒ 这条闸门正是它的样本**：**同一会话内我踩了三次**（`$L1（` / `$miss（` / `$out（`），**三次都只是我的命令**。
**⇒ 靠提醒显然不够**（第 32 / 34 条：**不许只靠提醒**）；**而检出成本是一条 grep。**

## 二、★ 而扫描当场抓到一个**真 bug**（闸门立刻赚回成本）

```
examples/claude-code/hooks/pretooluse-gate.sh:46
  echo "⛔ fail-closed: 引擎异常（exit $rc）—— 不得静默放行"
                                          ↑ 全角括号被吞进变量名
```

**⇒ 那条正是"引擎异常"时要输出的消息 ⇒ **它自己会失败**。**
**⇒ 而该 hook 的自述是"三层 fail-closed (T0-1)" ⇒ 它的 fail-closed 消息本身不可靠。已修为 `${rc}`。**

## 三、闸门本身（可双向证伪）

| | |
|---|---|
| `applies-to` | `**/*.sh`（引擎按首个匹配解析；**CI 第 4 步本来逐文件扫** ⇒ 全仓覆盖，不新增机制） |
| `check` | **跳过注释行** ⇒ `LC_ALL=C grep -E '\$[A-Za-z_][A-Za-z0-9_]*[^ -~]'`（不依赖 `grep -P`，macOS 没有） |
| 实测 | 基线绿 → 注入红 → **反例守住** · 全仓 **20 个 `.sh` 基线全绿** |

**⚠️ 两个必须记下的坑（都是"假红"的来源）：**
1. **注释里的 `$F（…）` 是说明文字、不是代码** ⇒ 判据**必须跳过注释行**，否则假红（`examples/fixtures/inject.sh:2` 就是这么一处）。
2. **修消息时我又踩了一次**：`${var}` 写在 `bash -c` 的字符串里**会被展开成空** ⇒ 消息要写 `\${var}`。
   **⇒ 这条闸门第一次运行的输出就是「必须写 ）」—— 它自己的消息踩了自己管的坑。**
