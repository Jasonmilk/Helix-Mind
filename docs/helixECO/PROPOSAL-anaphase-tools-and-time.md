# 跨仓提案 · anaphase：工具可用性与事件时刻（**工具链现已可用；两条隐患待修**）

> 2026-09-16 由 Cellrix 侧提出。**证据全部是代码行与实际事件文件**，不是推断。  
> 目的：让「模型为什么不调工具」与「时间戳代表什么」各自有一个**可判定**的答案。

## 一、结论（已由实测取代此前的推断）

**用户报「Tentacle / 搜索不可用」。根因是两层，都在我们这一侧，不在 tentacle、不在模型。**

### 结论先行：**真实启动路径（`Cellrix` 的 `up`）一直带着 `--plugins-dir`，工具一直加载成功。**
所以「模型看不到工具」**不是**第一层造成的——第一层只存在于测试壳里（见下）。

### 第一层（**测试壳的缺陷，已修，不是本回归的病因**）

- `Cellrix/web/src/bin/up.rs:420-426`：`tentacle … --plugins-dir <ws>/helix-tentacle/fixtures`
  —— 真实路径**一直是对的**。
- `Cellrix/web/tests/start-panel.sh`：**漏了**这个参数 ⇒ 测试壳里的 tentacle 零工具。
  ⇒ 这是**能力断言的反面**：测试壳与真实路径能力不同，**假绿**（页面全过，工具一个没有）。
  已修，并在 `ab_verify.sh` 加了静态守卫：测试壳的 tentacle 调用必须带 `--plugins-dir`。

### 第二层：注入格式把「来源分组」与「工具名」并列 —— **这才是本回归的病因**

**决定性实验（2026-09-16，用与 `up` 相同的配置：带插件）**：
一次真实对话，模型**确实发出了调用**，但它是：

```json
{"calls":[{"tool":"tentacle·fixture","name":"calc","args":{"expression":"8**6"},"expect":"ok"}]}
```

—— 模型把**组标签**当成了工具名。而该 period 里**只有 `attempt` 与 `turn/end`**，
**没有 `tool/call`，也没有 `tool/result`** ⇒ **调用发出而未被识别 ⇒ 未执行。**

⇒ 这解释了「以前可以、现在不行」：`2026-09-13 20:04` 成功那次，模型产出的是
`{"calls":[{"tool":"calc",…}]}`（`run-30fabc23294f31e6` 实证）——
**即分组前缀（`组标签: …`）是后来加的**，加完之后工具名就被组名顶掉了。

### 待改的那一行

修复后第一句真实调用暴露出格式缺陷：

```json
{"calls":[{"tool":"tentacle·fixture","name":"calc","args":{"expression":"8**6"},"expect":"ok"}]}
```

`main.rs:1034-1040` 每行是 `组标签: 工具A(签名): 描述 | 工具B(签名): 描述`。
模型因此把**组标签**读成工具名。**工具名与来源必须在格式上可区分**（例如每行一个工具，
来源放行尾括注，或改为 `calc(expression): 描述 [tentacle·fixture]`）。

### 被推翻的三条假设（留档，防止再走一遍）

| 假设 | 判定 | 证据 |
|---|---|---|
| 「tentacle 挂了 / 服务不可用」 | ❌ | 服务一直能起来 |
| 「换模型是回归根因」 | ❌ | 最后一次成功调用（`run-30fabc23294f31e6`，`2026-09-13 20:04`）的 `model` **就是 `agnes-2.5-flash`**；且历史 98 个 period 中 `tool/call` **共 24 次**、每次都伴随合法的 `{"calls":…}` |
| 「文本契约在新模型上失效」 | ❌ | 契约在 agnes 上被遵守过，2026-09-16 的复现里也立即被遵守 |
| 「启动脚本没加载插件是病因」 | ❌ | 真实路径 `up.rs:420` **一直带** `--plugins-dir`；缺参数只存在于测试壳 |

**回归窗口**：`2026-09-13 20:04`（最后一次成功调用）→ 之后 40+ period **tools 恒 0**。
与「启动脚本不再带 `--plugins-dir`」一致。

## 二、仍请 anaphase 做的两件事（与本提案同源，一并提）

### P0-A：**缺失必须留痕**（本提案的核心，与第一层的教训直接对应）

`main.rs:1003-1010` 是四层嵌套条件：**未配端点 / 连不上 / 列表为空** ——
三种失败产生**同一个可观测结果**：prompt 里没有这一段。于是「模型说没有工具」
与「系统忘了给」**完全同形**，这一个缺陷让上面那条排查走了十轮。

**请求**：把 `list_tools()` 的每一种结果写成**事件字段**（例如并进 `context/inject` 的 payload：
`tools: {status, count, endpoint, reason}`）。**Cellrix 只显示，不推导** ——
否则将来一定有人在视图层去猜（读 prompt 或另拉 endpoint），那又是一份推导。

**判据**：跑一轮后，**从事件流本身**能读到「本轮 tools 块：在 / 不在（原因）」。

### P0-B：工具名/来源的格式（见上「第二层」）

**判据**：同一句「用 calc 计算 8 的 6 次方」，模型产出的 `tool` 字段等于 `calc`
（不是组标签），且 `tool/result.ok == true`。

## 三、事件时刻（P1，本侧已修，不阻塞）

`session_events.rs:282 fn ts()` 逐事件生成、秒精度；同一轮的 `think/attempt/reply`
常共享同秒，而**请求侧**与**响应侧**之间的间隔**就是**该次调用时长。
Cellrix 侧已把 gap 读在**结束于本行**的那一端：THINK `[0,0,0] → [5000,3000,5000]`，

「模型行上它是整次调用，think 与 reply 由同一次调用产出，不可分解」。

**仍可选做（低优先）**：毫秒精度（把同批写入的事件按真实间隔分开）。

## 二·补：**组前缀不是回归边界**（已用日期否掉，留档）

曾有一个很自然的假设：注入格式由「裸名」改成「组标签: 名字 | 名字」是"以前可以、现在不行"的原因。
**代码史否掉了它**：

| 提交 | 日期 | 引入 |
|---|---|---|
| `b06fd25` `feat(ADR-0025): … tool-chain closure … calc/web_search` | 2026-09-07 22:09 | **工具块本身** |
| `93ecaca` `fix(criteria): … L1 schema-driven tiering` | **2026-09-09 05:31** | **组前缀**（`tentacle·fixture:` 与 `tentacle: {}` 同批出现） |

**而最后一次成功调用是 2026-09-13 20:04**（`run-30fabc23294f31e6`，产出裸名 `{"tool":"calc"}`）。
⇒ 组前缀**已经存在了 4 天**，那几次仍然成功 ⇒ **前缀不是边界，只是"有时会绊倒模型"的隐患**。

### 那么边界在哪？（未定，但已收窄到两条）

1. **`config.toml` 的 mtime = 2026-09-14 19:35** —— 恰在最后一次成功调用之后。
   但该文件被 `b4dc907`（`chore(sec): untrack deployment config`）**取消跟踪**，
   **无法 diff**：只能确认它**现在**含 `tentacle_endpoint = "http://127.0.0.1:50051"`。
2. **模型自述不可作为证据**：同一份 prompt 下，模型对"我有没有工具"的回答并不稳定
   （本轮在我的复现里它误报组名，在用户的复现里它用裸名成功）。

### 现状（2026-09-16 17:11 实测）

**工具链现在是通的**：用户环境一次真实对话产出
`{"calls":[{"tool":"calc","args":{"expression":"2**10"}}]}` → `tool/call calc` →
`tool/result {"ok":true,"result":"1024","duration_ms":595}`，`verdict: Met`，`success: true`。
⇒ 那条"4 天沉默"**已不再复现**；它要么是 09-14 前后的一次配置/进程状态，要么是模型侧的偶发。

### P0-C：注入格式的**可解析性**（不是"措辞"）

`main.rs:1034-1040` 每行 `组标签: 工具A(签名): 描述 | 工具B(签名): 描述`。
组标签与工具名**并列且无分隔语义**，模型会拿它当工具名（本轮实测到一次）。
**请求**：让「名字」与「命名空间」在格式上不可混——每行一个工具，来源放行尾括注，
或明确「`·` 只是命名空间分隔符，工具名是冒号前的第一个标识符」。
**判据**：同一句「用 calc 计算 8 的 6 次方」连续 5 次，`tool` 字段 5 次都等于 `calc`。

### P0-A 未变（且这次的排查过程就是它的证据）

三种失败（未配端点 / 连不上 / 列表为空）产生同一个可观测结果。**在它被修好之前，
任何"模型说它没有工具"的报告都无法与"系统忘了给"区分开** —— 上面那 4 天沉默至今无法定性的原因就是这个。

## 五、搜索：**已验**（注册齐全，现在能跑）+ 新发现：**工具循环只走一跳**

### 5.1 三条判据都取到了

| 判据 | 结果 |
|---|---|
| 工具注册 | `helix-tentacle/fixtures/` 含 `calc` / `numbers` / `rate` / `weather` / **`web_search`**（各含 `.manifest.json`）⇒ **注册齐全** |
| 历史调用 | `calc` ×18（末次 09-13 20:04）／`weather` ×4（末次 09-08 21:28）／**`web_search` ×2（末次 09-08 21:11，当时 `tool/result ok · 1407ms`）** |
| 现状（2026-09-16 17:4x 实测） | 问「今天北京天气，用 web_search」⇒ `tool/call web_search` → `tool/result {"ok":true,"results":[…]} · 1071ms`，两道 check 均 PASS |

⇒ **搜索不是"从未可用"，也不是"没注册"**；三个工具**停在不同日期**，这个形状指向"调用发生与否"而不是"某工具坏了"。

### 5.2 新发现（本次实测）：**二次调用不执行，且以 JSON 形式当成回复**

同一轮的 `turn/end.reply` 是：

```
网络搜索的结果与天气无关，我使用天气工具来查询。
{"calls":[{"tool":"weather","args":{"city":"Beijing"},"expect":"ok"}]}
```

**第一次调用执行了，第二次没有** —— 它被当成"回复"写进了交付物。用户因此看到一段 JSON 而不是答案。
⇒ **工具链是"打一下"而不是"循环"**。这解释了用户报的第二种形态（"该用工具却没用"）的一部分：
模型想连续用两次时，第二步永远不会发生。

**请求**：明确工具循环的**次数上限与其可见性**。若上限是 1，那么"超出上限的第二次调用"
必须**不是**回复的正文（否则等于把内部意图当交付物）；要么执行，要么显式声明"已达上限"。

**判据**：同一问连续 3 次，`turn/end.reply` 都不含 `{"calls"` 子串，且 `tool/call` 的次数 ≥ 1。

### 5.3 间歇性（这条改变优先级判断）

同一环境、同一模型：**09-16 三轮"该用工具却没用"（失败）**，**09-16 17:11 与 17:4x 两轮成功**。
⇒ **该缺陷是间歇性的，不是一次性的沉默。** 间歇性故障**无法靠复现定位**，
所以 P0-A（每次记录本轮 tools 块在/不在 + 原因）**不是可选项，而是唯一可用的诊断手段** ——
否则下一次失败我们仍然只能猜，并且会再把"模型自述"当成证据。
