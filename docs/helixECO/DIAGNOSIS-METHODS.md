## <a id="no-thread-stack"></a>`no-thread-stack` · 挂起任务没有线程栈帧

**陈述**：任务被 poll 时 future 树在线程栈上展开；返回 `Pending` 的瞬间整棵栈退回堆上的状态机。
⇒ **线程采样只看得见"正在 poll"的帧**（即 busy spin），**看不见"挂起等 IO"与"任务已死"**。
**能红的证明法**：采一个**已知挂起**的任务 ⇒ 采样输出里**找不到**它；采一个 busy spin 的任务 ⇒ 找得到。
**收据**：K25 排查中我据采样误判"运行时在空转"，实际是 Err 已返回、测试正在轮询。
**边界**：适用于任何 async runtime（任务模型共通）；**不适用**于 OS 线程（那有真栈）。

## <a id="silent-instrument"></a><a id="red-lifecycle"></a>`red-lifecycle` · 红的生命周期（旧名 `silent-instrument`）

> **一条完整纪律的三个阶段**（原第 6 条 + 2026-10-09 两个新标本合并而来 —— 见头部"入库守则"）：
> **① 必须能红**（原本的 `silent-instrument`）· **② 红了必须作数** · **③ 不能总是红**。

### ① 必须能红 —— 静音仪器不能当证据

**陈述**：一个**没有订阅者的** `warn!`/`info!` **什么都不输出** ⇒ 它的"无输出"**不是阴性证据**。
**b（更锋利）：静默的腐败机制是"产出零"，而零在阅读时冒充阴性**（"没有 doctest""该分支未走""没有孤儿文件"）。
**纪律**：任何"零"在被当成阴性之前，**必须先证明产生它的仪器活着**。
**收据**：K25（`grep 'Pipeline execution failed'` = 0 次，实为无订阅者）；同族：PATH 写错 + `2>/dev/null` 得到三个 0；
普通 `git status` 隐藏 `.gitignore` ⇒ 零冒充"干净"。

### ② 红了必须作数 —— 别让裁决被静默丢弃

**陈述**：检查**跑了、也印了**，但它跑在**它要影响的那个状态初始化之前**（如 `fail=0` 那一行之前）
⇒ **裁决被丢弃**。症状比静音**更隐蔽**：**输出看得见（人以为它在守），影响不作数（实际没守）**——
**静音的仪器什么都不说；这个会大声说错话。**
**能红的证明法**：故意让该检查失败 ⇒ **总结行必须跟着变**（如"五步全绿"→"不要推送"）。
**收据**：2026-10-09 引擎清单那一步（第一版插在 `fail=0` 之前 ⇒ 印 ★ RED 而总结仍全绿）。

### ③ 不能总是红 —— 永远红的检查会教人忽略红灯

**陈述**：检查的**取值口径与生成口径不一致**（如一处带 `tools/` 前缀、另一处不带）⇒ **无论对错都报红**。
后果是**警报疲劳**：当红灯大多是"我知道怎么回事"时，**真篡改与真漂移会混在已知失配里一起被忽略**。
**能红的证明法**：跑三向自测 —— **真绿 0/N · 真红 N/N · 不存在的输入 N/N**。
**收据**：2026-10-09 `redrate.sh` 的第一版（只认 cargo test 形状的输出 ⇒ 命令不存在时报 0/N【能绿】）；
同族：六仓 sha 校验的**同步滞后**会制造常态红（SOP 见 phyt-DNA `docs/PROTECTION.md`）。

**陈述**：一个**没有订阅者的** `warn!`/`info!` **什么都不输出** ⇒ 它的"无输出"**不是阴性证据**。
**b（更锋利）：静默的腐败机制是"产出零"，而零在阅读时冒充阴性**（"没有 doctest""该分支未走""没有孤儿文件"）。
**纪律**：任何"零"在被当成阴性之前，**必须先证明产生它的仪器活着**（先产出一次非零，或先确认它跑过）。
**能红的证明法**：故意制造一个**必然触发**的日志点 ⇒ 若输出里**没有**它 ⇒ 该仪器是静音的（判据应红）。
**收据**：K25（`grep 'Pipeline execution failed'` = 0 次，实为无订阅者）· 同族：PATH 写错 + `2>/dev/null` 得到三个 0 ·
普通 `git status` 隐藏 `.gitignore` ⇒ 零冒充"干净"。
**边界**：适用于一切"以输出为证据"的仪器；正解不是"记住它可能静音"，而是**让它不再静音**。

## <a id="memory-pattern"></a>`memory-pattern` · 凭记忆写的 pattern / 条件不能当证据

**陈述**：grep 的 pattern、`starts_with` 的判定条件、字段的形态 —— **凭记忆写的一律不算证据**，
必须**对着源码字面量逐字核**。
**能红的证明法**：写一个**故意错一位**的 pattern ⇒ 它必须**匹配不到**（否则你的判据本身在自欺）。
**收据**：K25 我凭记忆以为 `"bypass"` 的表达式是 `Some("rail")`（真字节是 `serde_json::json!("rail")`）⇒ 正则 0 匹配、替换落空；
K26 我**逐字核**了 `"blocked by security gate: "` 前缀 ⇒ 结论比预期更干净（只有一处构造点 ⇒ 不需要 skip）。
**边界**：对"我写的代码"同样适用（尤其**我自己刚写的**）。

## <a id="waiting-vs-lost-waker"></a>`waiting-vs-lost-waker` · 「等一个不可能到来的事件」≠「唤醒丢失」

**陈述**：两者外观都是"卡住不返回"，但**修法方向完全相反**：
前者是**调用已经失败**、测试在等结果（改等待逻辑/改断言）；后者是 **waker 丢了**（改调度/改同步原语）。
**能红的证明法**：把等待上限**加长一个数量级** ⇒ 若仍然不到 ⇒ 倾向于"不可能到来"；若到了 ⇒ 是赛跑/慢。
**收据**：K25 —— 我一度画像成"永不唤醒的 future"，真因是**服务器已停 accept、调用已失败**。
⚠️ 用**有上限**的仪器断言"永不到"是无效推理（我拿 2s 上限说"C 不存在"，实际只是超过 2s）。
**边界**：async/await 与任何超时机制；不适用于"确实永远阻塞"的同步死锁（那要看栈）。

## <a id="underscore-drop"></a>`underscore-drop` · `_` 与 `_x` 的 Drop 语义陷阱

**陈述**：`let _ = x` **立即** drop；`let _x = x` **活到作用域结束**。
而当被丢对象是 `oneshot::Sender` 这类**Drop 带协议副作用**的东西时，
"我只是不想用它"**会变成"我发出了一个信号"**。
**能红的证明法**：把 `_tx` 改成具名并**在作用域内持有** ⇒ 行为应发生变化（K25：20 次约 25–28 失败 ⇒ 20/20 全绿）。
**收据**：K25 根因（`_tx` 在函数返回时 drop ⇒ oneshot 接收端立即 resolve ⇒ 服务器停止 accept）。
**边界**：Rust 系；**现有 lint（如 `let_underscore_future`）不覆盖**"丢弃带 Drop 副作用的字段"。

## <a id="green-is-a-sample"></a>`green-is-a-sample` · 绿是小样本抽样，红率 N≥20 才有资格说话

**陈述**：单次绿说明不了任何事。**红率（N≥20，并行+串行双模式）**才有资格说话。
**姊妹条：消失要追因** —— "某测试好了/不见了"与"绿了"同属**成功断言**，同样有第三态
（小样本绿 / 他因被顺手修掉）⇒ 必须给出**结构性或观测性**的因果。
**能红的证明法**：把修复撤掉 ⇒ 红率必须回到基线；**主证优先用结构性论证**（如"失败路径与本条修复路径不相交"）。
**收据**：K25 —— 我曾据"8/8 绿"宣布"它现在不红了"，而同一命令 20 连跑是 **19/20 有红**；
K25 销案时 `the_override` 的"消失"我用**路径不相交**作主证（时序只作佐证）。
**边界**：一切"用运行结果下结论"的场合。

## <a id="ask-the-third-state"></a>`ask-the-third-state` · 每个二分先问第三态

**陈述**：把"非黑即白"的二分**先扩成三分**。本轮三个二分**各漏一支，且漏的那支先验最高**：
- "断言读数为 0" 漏了 **C（断言早于完成）**；
- "采样看见什么" 漏了 **挂起任务无栈帧**（死 / 挂 / busy）；
- "grep 无输出" 漏了 **仪器本身静音**。
**对成功断言同样适用**："绿了 / 消失了"也有第三态（小样本绿 / 他因被顺手修掉）。
**能红的证明法**：写出三分后，**逐个分支给出一条判别实验**；若某分支无法判别 ⇒ 明说"该分支未判别"。
**边界**：一切"要么 A 要么 B"的推理。
