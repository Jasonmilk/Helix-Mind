# 目标 2 前提**被否证** —— 它与目标 1 是同一个病（展示投影，不是写侧空写）

## 一、实测（真实 store `.helix/events`，最近 60 轮）

```
context/inject 共 60 条，其中空 0 条
平均每轮 1.0 条 inject、空 0.0 条
```

⇒ **一个 period 恰好 1 条 `context/inject`，且没有一条是空的。**

## 二、⇒ 人类报告的前提（"一轮 98 个事件，其中约 90 个是空的"）在**事件流层不成立**

人类在面板上看到的是：

```
Turn 1 · 98 events
  CONTEXT  context inject · SA-Core selection · nodes=— chars=—   × ~90
```

**"~90" 不是事件流里的 90 条事件，是面板列出的 90 行。**
⇒ 这与**目标 1 是同一个病**：detail 把**一条血缘路径上多个 period 的行并列显示**。

| 观察 | 真因 |
|---|---|
| "90 行" | 路径上各 period 的 `context/inject` 行**加在一起**（不是一轮 90 次） |
| `nodes=— chars=—` | **渲染时取不到字段**（字段映射），**不是**事件里没有数据 |
| "98 events / 291 steps 是全局的" | 同上 —— 是**这条链的并集**，不是全局 |

## 三、这与 CQRS 分析的结论**不同**，必须更正

人类原判：「~90 个空 CONTEXT = 注入在循环里被反复调用 = **写侧**的病」。

**实测否证**：写侧是干净的（每轮 1 条、非空）。
⇒ **它是读侧的病（展示投影），与目标 1 同源。**
⇒ **三条病不是一个根**（至少这条不是写侧）—— 这一点我按实测更正，不硬套框架。

## 四、因此两个目标**合并**，处置也合并

**目标 1 = 目标 2 = 展示投影（P3）**。修 P3 时**必须同时**满足：

1. 点开 X ⇒ 只含 X 自己的行（其他 period 作为**具名链接**出现，**标明归属**）
2. `nodes`/`chars` 这类字段**取不到时要显示具名缺失**，不得显示成 `—` 而让人以为是"事件里没有"
3. 没有选中 ⇒ **具名空态**，不得是全局或某条祖先链
4. 变异：去掉"标明归属" ⇒ 必红
