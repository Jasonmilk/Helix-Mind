## 一、落地了什么（两条轴）

**第二根轴进账本**（`web/tests/run_all.js`）：

```json
"fingerprint": "014136d71751",
"validity": {
  "gatesWithFixture": 1,
  "provenWithoutFixture": 78,
  "falseGreenRisk": "PARTIAL",
  "redIsAttributable": "see RED ROSTER (a count is not attributable)"
}
```

**时序轴**（`tools/determinism.sh`）：同命令两次 → 指纹不同 ⇒ **`FLAKY`（既非红也非绿），不得作为证据**。
**★ 默认免费**：指纹每次运行都已写进账本 ⇒ **比较不需要重跑**。
（第一版会重跑整套 ⇒ 每次 ≈7 分钟，不可用；**而答案一直在账本里** —— 这是本轮的一个设计教训。）

## 二、★★★ 第一次读数：**假绿被量化了**

```
"provenWithoutFixture": 78      ← 79 个「proven」里，78 个没有任何夹具
```

**⇒ 它们**从未被证明过会红**。按 Ω，那不是"绿"，是**未测量**。**
（这正是 P3「零闸门」的推广：**一组 gate 全绿而没有夹具 ≠ 绿**。）
**⇒ 而这条读数以前不存在** —— 我这几轮报告的"79 proven"**从未带过这个限定**。

## 三、★★★ 第二次读数：**同环境 8 次运行，6 种指纹**

```
env cdp=up panel=up jsdom=no (simulated): 3 次 · 唯一指纹 3 ⇒ FLAKY    proven 53..55  red 2..4   held 31..31
env cdp=up panel=up jsdom=yes:            5 次 · 唯一指纹 3 ⇒ FLAKY    proven 76..79  red 7..10  held 1..1
```

**⇒ 三个结论：**

1. **`jsdom=no/yes` 解释了 `held 31 ↔ 1` 的大跳** ⇒ **P6（账本带环境）确实抓到了这一层** ✅
2. **但同一环境内指纹仍不一致**（3/3、3/5）⇒ **P6 之后仍有真非确定性** ⇒ **P11 抓的是这一层**
3. **⇒ 本会话我报告的每一个「79 proven / 3 red / 6 red」都不是测量** ——
   **它们每次都不一样，而且我在报告时并不知道。**

**⇒ P6 必要但不充分；P11 补上的是"裁决是否可信"这一维。这正是人类说的"测电仪"。**

## 四、对人类"时序场景"的落实

**时序被做成了**可判定的**：**
- 每次运行写 `fingerprint`（红名单 + 计数的哈希）
- `determinism.sh` **只比较环境相同的运行**（不同的环境本来就不可比 —— P6 的纪律）
- 不一致 ⇒ **`exit 2` + 明确措辞**："该裁决既不是红也不是绿，不得作为证据"

**⇒ 这就是"假红"的机械识别**：不是判据错，而是**同一命令答两次不一样**。
