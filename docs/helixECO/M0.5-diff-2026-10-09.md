## 一、实验设计

| 项 | 值 |
|---|---|
| 唯一变量 | **FlowModus 在 / 不在推理路径** |
| 共同上游 | `llama-swap @127.0.0.1:8080/v1` · model `coder-3b`（**本地，零外网成本**） |

> anaphase 报 `h2 protocol error: frame with invalid size` ⇒ 一个命名相近、职责不同的接缝。

## 三、结论

### 3.1 选项 3 **被排除**

> 原诊断的三选一：「① ADR-0041 没修完 / ② A1–A5 之外的新成因 / ③ 痛感来自 FlowModus 那一半」

- **① 排除**（阶段一）：462 period 上覆写/多组/非单调全 0，在最硬语料（219 次同输入）上被证实。
- **③ 排除**（本阶段）：FlowModus 在/不在，DAG 拓扑**逐项相同**。
- ⇒ **只剩 ②**，而 ② 的具体落点已被定位（见 3.2）。

### 3.2 剩余成因：**不是写路径，是 I5**

A1–A5 的现状（2026-10-09 实测）：

| # | 现状 | 证据 |
|---|---|---|
| A1 | ✅ 已修 | 462 period 全部 1 组 `turn/start` |
| A2 | ✅ 已修 | 非 id 父 0 / 悬空 0 |
| A3 | ✅ **已修** | `Cellrix:web/assets/chat.js:203` 双键 `job_id == j.job_id && parent == sentAnchor` + 有界重试 + **禁止"取最新"回退**（owner 裁决 2026-10-04） |
| A4 | ✅ 已修 | `chainJobIds` = 血缘路径（`Cellrix:ADR-0021`） |
| A5 | ✅ 已修 | 倒置 0 |

**⇒ 写路径是干净的。** 剩下的缺口是 **I5：`slice`（从选中根出发的可达闭包）没有成为命名、可独立断言的原语。**

- `panel_tree.js:266` 确有一个前向子树遍历（`children` 由 `parent` 建），但它**依附于树渲染**，不是独立原语；
- `chainJobIds` 只能向**后**走（祖先链）——两者不是同一个东西（见 `anaphase:ADR-0047`）。

### 3.3 顺带：阶段一「72.5% 孤根」的解释闭合

新语料上 **6 根 / 7 period**，且**续接正确成链**。
⇒ 旧库 72.5% 根占比是 **84% 重复探针输入**的产物（一个输入 219 次），**不是链断裂**。
⇒ **M7 的「83 → 可接受」不能用探针库判定**；判据必须落在**多样语料**上。

## 四、对计划的修正（增量）

| 项 | 修正 |
|---|---|
| **M2** | = **验收 + 补缺口**。写路径已验收通过；缺口是 **I5**，落在 Cellrix（不是 Anaphase） |
| **M3 / I4** | **口径修正**：严格「父 < 子」在**秒级**精度下会**误报同秒续接**（本地 3B 一轮 < 1s，实测 1 次并列）。⇒ 断言须写成 **父 ≤ 子**，或补亚秒精度。否则 M4 的变异测试会把"精度"当成"缺陷"来杀 |
| **M3 / I5** | 断言对象是**可达闭包的命名原语**，不是"树渲染里有个 count" |
| **M6** | 仍是 **B18**（`period_id` 传播到 Tuck），见 `ADR-0041` §7.2 |
| **M7** | 基线改用**多样语料**，不用探针库 |
