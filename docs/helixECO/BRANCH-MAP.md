### ★ Trap 38（新）：**"合并已完成、等你提交"必须被读出来**

```
实测：`git merge` 因提交信息被 shell 吃掉而中止提交 ⇒ git 打印 **"Not committing merge; use 'git commit' to complete the merge."**
⇒ **合并其实成功了，只是停在暂存**；而我把它读成失败，进而得到两个错结论（"有冲突"、"干跑不可靠"）。
⇒ **判据**：合并后**先看 `git log -1 --format=%p`（父的个数）**，再看 `git status`（是否 A/M 暂存）；
   **不要从一句 stderr 推断成败**（"红了要故事"同样适用于"失败要有名字"）。
⇒ **机械修**：提交/合并信息一律走文件（`tools/msg.sh` + `-F`）—— **不改小心，改组织**（Trap 37 的正解）。
```
