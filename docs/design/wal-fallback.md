# WAL 回退方案（P4.5 架构审查点产出 ④）

> **状态**：回退预案（仅在 ADR-0015 原型验证失败时启用）
> **日期**：2026-08-28
> **触发条件**：WAL 最小原型验证失败——延迟不达标（SSD p99 ≥ 10ms 持续）或崩溃恢复不可靠（截断恢复丢失完整记录）。

## 一、原型验证现状（2026-08-28）

- **append + fsync + 单段读取**：✅ 全部通过（4/4 测试）。
- **延迟实测**：单条 fsync p50=3.17ms / p99=6.53ms（SSD），**<10ms p99 达标**（审查③ F8 目标）。
- **崩溃恢复**：截断尾部被安全忽略，完整记录保留，语义正确。
- **当前结论**：原型验证通过，P5 可进入全功能实现。本回退方案为诚实预案，不触发。

## 二、回退触发条件（后续 P5 若发现）

1. 全功能 WAL（段轮转 + 哈希链 + 异步投影 + replay）在某环节延迟/可靠性不达标。
2. 多租户 / 高并发下 WAL 写放大不可控，且无修复路径。
3. 哈希链完整性校验暴露不可接受的位腐坏率（存储介质级问题）。

## 三、回退方案（降级，不推翻）

**降级目标**：回到"SQLite 事务 + deferred_writer 投影器"（当前实现的增强版）。

| 项 | 降级实现 |
|---|---|
| 事实来源 | SQLite 事务（`write_node` 原子提交） |
| 投影 | `deferred_writer`（异步批量回刷，已存在） |
| 溯源 | 有限（无全量 push 历史；仅节点级 upsert） |
| 副本回退 | 不支持（无 WAL 快照） |
| 哈希链 | 不适用（SQLite 自带页校验） |

**代价（诚实声明）**：
- 放弃全量溯源（"可以回退或快进每个副本"不可达）。
- 事实来源与投影仍混居 SQLite（回到被 ADR-0015 否决的架构，作为生存性降级）。
- 性能：写入放大受 SQLite WAL 模式限制，但可接受（单机量级）。

## 四、恢复路径

- 降级是**生存性**选择（不是目标）。若未来硬件/存储条件改善，新 ADR Supersede 本降级，重新启用领域 WAL。
- 所有 WAL 相关接口（`helix-mind-wal` crate）在降级期保留编译，作为未来恢复的接缝。

## 五、决策记录

- 本方案随 ADR-0015 进入 P5。P5 每一功能里程碑结束时复检：是否触发回退。
- 触发回退需用户确认（重大架构降级，不静默执行）。
