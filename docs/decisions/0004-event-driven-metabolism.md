# ADR-0004: 事件驱动代谢替代定时轮询

## 状态

采纳（2026-06-24）

## 问题

定时轮询（如每 5 分钟执行一次 Micro-Sleep）浪费 CPU 周期，在系统空闲时无意义地唤醒，在高负载时可能干扰正常请求。

## 决策

- 代谢完全由事件驱动：L3 写入计数达到阈值、系统空闲检测、用户显式触发
- 使用 `tokio::select!` 检测空闲，非定时器
- 空闲检测可被任何新到达的请求立即打断，不消耗 CPU 周期等待

## 权衡

| 优势 | 代价 |
|:---|:---|
| 零空闲浪费 | 代谢触发时机不确定，可能延迟 |
| 高负载时不干扰 | 需要合理设置触发阈值 |
| 符合"绝无心跳"铁律 | 调试时需要理解异步事件流 |

## 回滚阈值

若代谢延迟导致 L3 碎片过度堆积（超过内存容量 80%），则引入轻量级定时兜底（如每 24 小时强制触发一次 Deep Dream）。

- 极致节能（公理七）
- 铁律 13：绝无心跳，事件驱动
